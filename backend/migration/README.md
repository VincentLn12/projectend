# ย้ายข้อมูลจากเว็บเดิม (Webcomcs) มายัง ComSciDb

สคริปต์ `MigrateFromWebcomcs.sql` คัดลอกข้อมูลจากฐานข้อมูลเดิมเข้าฐานข้อมูลใหม่ในครั้งเดียว ทำงานใน transaction เดียว (พลาดตรงไหนย้อนกลับทั้งหมด) และรันซ้ำได้โดยไม่ซ้ำซ้อน

## ก่อนรัน

1. restore `Webcomcs.bak` เป็นฐานชื่อ `Webcomcs` บน SQL Server เครื่องเดียวกับ `ComSciDb`
2. สร้างฐานใหม่ด้วย `dotnet ef database update` (จากโฟลเดอร์ `backend`)
3. เปิด API หนึ่งครั้ง เพื่อให้ระบบสร้าง role ทั้ง 4 และแอดมินคนแรก (สคริปต์ตรวจและหยุดถ้ายังไม่มี)
4. สำรอง `ComSciDb` ไว้ก่อน (ถ้าฐานมีข้อมูลจริงอยู่แล้ว)

```bash
sqlcmd -S .\SQLEXPRESS -E -C -I -f 65001 -v SourceDb=Webcomcs TargetDb=ComSciDb ShowProfile=0 -i MigrateFromWebcomcs.sql
```

ท้ายสคริปต์พิมพ์รายงานจำนวนแถวที่เพิ่ม และจำนวนที่ข้ามโดยตั้งใจ

## กติกาที่สคริปต์ใช้

| ข้อมูลเดิม | ทำอย่างไร |
|---|---|
| ผู้ใช้ `IsUsed = 0` (6 คน: บัญชีทดสอบ/ปิดใช้งาน) | ไม่ย้าย รวมถึงประวัติทำงานและการลงทะเบียนอบรมของบัญชีเหล่านั้น |
| รหัสผ่าน | คัดลอกแฮชตรงๆ (ทั้งสองระบบใช้ ASP.NET Identity v3) ผู้ใช้เดิมล็อกอินด้วยรหัสเดิมได้ |
| ประเภทผู้ใช้ | ดูจาก role เดิม: Admin > Lecturer > Student > อื่นๆ (บัญชีที่เป็นทั้ง Admin และ Lecturer ได้ประเภท Admin) |
| นักศึกษา | รหัสนักศึกษา = ชื่อผู้ใช้เดิม, ปีที่เข้าเรียน = เลข 2 หลักแรกของรหัส + 2500 (ไม่ใช้ `YearEdu` เดิมเพราะไม่ตรงกับรหัส) |
| รหัสของโครงงาน ข่าว หลักสูตร รุ่น (ข้อความเช่น `PROJ…`) | สร้าง GUID จากรหัสเดิมแบบคงที่ (รหัสเดิมเดียวกัน ได้ GUID เดียวกัน) |
| ปีการศึกษาของโครงงาน | ฐานเดิมไม่มี จึงคำนวณจากวันที่สร้าง (ปีการศึกษาเริ่มมิถุนายน: ม.ค.–พ.ค. นับเป็นปีก่อนหน้า) |
| ปีของหลักสูตร | เดิมเป็น ค.ศ. (2026) บวก 543 เป็น พ.ศ. (2569) |
| หลักสูตรปัจจุบัน | หลักสูตรที่แสดงอยู่และปีใหม่สุด |
| หน่วยกิตรวมของหลักสูตร | ผลรวมหน่วยกิตของรายวิชา (เว้นว่างถ้าเกิน 400) |
| อาจารย์ที่ปรึกษา (เดิมเป็นข้อความ) | จับคู่ชื่อกับตารางอาจารย์ (ตรงทั้งชื่อ หรือข้อความมีชื่ออาจารย์อยู่ภายใน) ชื่อที่จับคู่ไม่ได้สร้างเป็นอาจารย์แบบไม่เผยแพร่ ทุกคนเก็บเป็นที่ปรึกษาหลัก เพราะข้อมูลเดิมไม่ระบุ |
| แถวที่ปรึกษาที่โครงงานไม่มีอยู่ (139 จาก 166 แถว) | ข้าม |
| บัญชีอาจารย์ / ผู้สอนหลักสูตร | สร้างอาจารย์แบบไม่เผยแพร่ ให้หลักสูตรอ้างถึงได้ |
| ลิงก์โครงงาน | ค่าว่าง หรือ `-` กลายเป็นไม่มีค่า และตัดช่องว่าง |
| ตั้งค่าเว็บ | เขียนทับแถวเดียวที่มีอยู่ เฉพาะตอนที่ยังเป็นชื่อเริ่มต้นของระบบ (รันซ้ำจึงไม่ทับสิ่งที่แก้ในระบบใหม่) |

ลำดับของวัตถุประสงค์และอาชีพหลังจบ เดิมไม่มีคอลัมน์ลำดับ จึงเรียงแบบคงที่แต่ไม่รับประกันว่าตรงกับของเดิม ผู้ดูแลจัดลำดับใหม่ได้ตอนแก้หลักสูตร

## สิ่งที่ต้องตัดสินใจ / ทำต่อหลังย้าย

- **ความยินยอมแสดงชื่อ (PDPA)**: ผู้ใช้ที่ย้ายมาทุกคนเริ่มที่ `ShowProfile = 0` (ซ่อนชื่อบนหน้าสาธารณะเป็น "ไม่ระบุชื่อ") และไม่มีวันที่ยินยอม เพราะเดิมไม่เคยบันทึกไว้ ถ้ามหาวิทยาลัยยืนยันว่าแสดงต่อได้ ให้รันด้วย `ShowProfile=1` หรือสั่งภายหลัง: `UPDATE dbo.Users SET ShowProfile = 1 WHERE UserType = 2;` (ควรให้ผู้รับผิดชอบนโยบายข้อมูลส่วนบุคคลยืนยันก่อน)
- **ไฟล์รูปและ PDF**: ฐานเดิมเก็บแค่ชื่อไฟล์ (109 ไฟล์) สคริปต์สร้างแถวไฟล์ที่มี path `legacy/<ชื่อไฟล์>` คัดลอกไฟล์จากเซิร์ฟเวอร์เดิมมาไว้ที่ `backend/src/ComSci.Api/uploads/legacy/` แล้วรูปจะแสดงทันที (ก่อนคัดลอกจะได้ 404) ขนาดไฟล์ในตารางเป็น 0 ไปก่อน (ใช้แสดงผลเท่านั้น)
- **แอดมิน**: แอดมินเดิม 2 คนย้ายมาพร้อมรหัสผ่านเดิม เมื่อยืนยันว่าล็อกอินได้แล้ว ควรล็อกหรือลบบัญชี `admin@comsci.local` ที่ระบบสร้างให้ตอนเริ่มต้น
- **ข้อมูลสาธารณะที่เห็นแล้วก่อนเปิดใช้งานจริง**: ตรวจหน้าโครงงาน ข่าว และหลักสูตรอีกรอบ

- **ล้าง HTML**: เว็บเดิมเก็บข้อความจากตัวแก้ไขแบบมีรูปแบบเป็น HTML (ความเชี่ยวชาญอาจารย์ รายละเอียดโครงงาน เนื้อหาข่าว รายละเอียดรุ่น/วิชาเทคโนโลยี/หลักสูตร) หลังย้ายให้รัน `CleanHtmlFields.sql` เพื่อแปลงเป็นข้อความธรรมดา (แท็กบล็อกกลายเป็นขึ้นบรรทัดใหม่ รูปและลิงก์ในเนื้อหาถูกตัดทิ้ง) รันซ้ำได้ปลอดภัย ต้นฉบับ HTML ยังอยู่ในฐาน Webcomcs:

```
sqlcmd -S .SQLEXPRESS -E -C -I -f 65001 -d ComSciDb -i CleanHtmlFields.sql
```

## รันซ้ำ

รันซ้ำได้ แถวที่มีอยู่แล้วจะถูกข้าม แถวลูก (รายวิชา รูปข่าว ฯลฯ) จะถูกเพิ่มให้เฉพาะแม่ที่ยังไม่มีลูกเลย จึงไม่ซ้ำแม้ผู้ดูแลแก้ในระบบใหม่ไปแล้ว (ถ้ารันสคริปต์ย้ายใหม่กับฐานที่ว่าง ต้องรัน CleanHtmlFields.sql ซ้ำอีกครั้งหลังย้าย)
